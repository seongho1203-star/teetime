# 안드로이드 대화 화면을 코틀린으로

> **아이폰과 똑같이 맞출 일감 목록은 `docs/안드로이드-따라잡기.md`에 있다.**
>
> **이 문서의 코틀린 작업은 GPT가 맡는다**(사용자가 정했다 — `스위프트는 클로드,
> 코틀린은 GPT가 개발할거야`). Claude는 `android/`를 고치지 않고, 웹 쪽 다리
> (`src/lib/native-*.ts`)를 바꿀 때 무엇이 바뀌었는지 알린다. CLAUDE.md
> `사용자 지침` 참고.

사용자 요청 — `이제 앱은 완성된거같은데 안드로이드도 아이폰처럼 앱으로
만들고싶어. 코틀린으로`. 앞서 정해 둔 방향 그대로다(CLAUDE.md —
`나중에 안드로이드도 채팅은 아이폰과 같이 앱으로만 만들거야`).

**'아이폰처럼'이 뜻하는 것** — 아이폰 앱은 껍데기(Capacitor)에 **대화 화면만**
Swift로 따로 지은 것이다(홈·라운드·투표·공지는 웹 그대로). 안드로이드도
같은 꼴로 간다: 껍데기는 이미 있고(`android/`, 알림·카카오 로그인까지
돈다), **대화 화면만 코틀린으로** 짓는다. 앱 전체를 코틀린으로 다시 짓는
것이 아니다.

## 여기서 확인할 수 있는 것과 없는 것

- **여기서는 안드로이드를 컴파일할 수 없다.** 안드로이드 SDK를 받는
  구글 저장소(`dl.google.com`)가 이 환경에서 막혀 있다. 코틀린이 컴파일되는지는
  **GitHub의 우분투 빌드(`android.yml`)** 가 알려 준다 — 밀면 10분쯤 뒤에
  초록/빨강이 갈린다. 아이폰 Swift를 맥이 컴파일해 주는 것과 같은 길이다.
- **화면이 제대로 도는지는 안드로이드 폰에서만 보인다.** 빌드가 남기는
  `kkakkung-apk`를 폰에 넣어 본다(아래). 저장소 주인 폰은 아이폰이라
  **안드로이드 폰을 하나 빌려야 한다.**
- 나중에 시뮬레이터 검사(아이폰의 `NativeChatTests.swift` 몫)를 GitHub의
  안드로이드 에뮬레이터로 돌릴 수 있다 — 3단계에서 붙인다.

## 단계

한 판을 다 짓고 켜는 것이 아니라, **켜는 스위치를 두고 단계마다 밀어 올린다.**
스위치가 꺼져 있으면 안드로이드는 지금처럼 웹 대화 화면을 쓴다 —
그래서 만드는 동안에도 안드로이드로 쓰는 회원에게는 아무 변화가 없다.

| 단계 | 넣는 것 | 확인 |
|---|---|---|
| **1** | 플러그인(`NativeChat`) · 통신(REST + 실시간) · 말풍선 목록(글·사진·이모티콘·안내·눌리는 카드) · 글칸·보내기 · 읽음 · 카드 눌러 이동 · 뒤로 | 빌드 초록 · 폰에서 대화가 뜨고 보내지고 실시간으로 받는가 |
| 2 | 반응(😄 2) · 댓글(답장) · 길게 누른 창 · 사진 크게 보기 · 이모티콘 서랍 · 추천 줄 · 고른 이모티콘 카드 | 폰 |
| 3 | 검색 · ☰ 서랍(사진·참여자) · 전체화면 프로필 · 사진·동영상 올리기 · 폭죽 · 끌어서 뒤로 · 에뮬레이터 검사 | 폰 + GitHub 에뮬레이터 |
| 끝 | 스위치를 없애고 안드로이드 기본을 앱 대화로 | `hasNativeChat()`의 android 갈래 |

## 켜는 방법 (시험 중)

1. `android.yml` 실행 화면 아래 `kkakkung-apk`를 받아 안드로이드 폰에 깐다
   (알 수 없는 앱 설치 허용이 필요하다).
2. 카카오로 로그인한다.
3. `내 정보` 맨 아래 **`시험 중: 앱 대화 화면`** 스위치를 켠다.
4. `대화` 탭을 누른다 — 코틀린 화면이 뜬다. 끄면 예전 웹 대화로 돌아간다.

## 짜임 — 아이폰과 이름을 맞춰 둔다

```
android/app/src/main/java/com/kkakkung/app/chat/
  NativeChatPlugin.kt     ← ios/App/App/NativeChatPlugin.swift
  ChatService.kt          ← NativeChatService.swift (REST · 실시간 · 설정)
  ChatRows.kt             ← NativeChatRows.make (말풍선 한 줄의 재료)
  ChatListView.kt         ← ChatList.swift (목록 · 말풍선 그리기)
  ChatScreen.kt           ← NativeChatViewController.swift (화면 전체)
  Iso.kt                  ← 날짜 셈(한국 시각)
```

- **웹과 오가는 신호는 아이폰과 똑같다**(`src/lib/native-chat.ts`) —
  `open`·`close`·`session`·`reset`, 그리고 `event`(`navigate`·`read`·
  `auth`·`back`). 웹 쪽은 한 줄도 갈리지 않아야 한다.
- **규칙은 웹에 있는 것을 그대로 받는다** — 반응 다섯(`REACTIONS`) ·
  이모티콘 목록 · 추천 표(`suggestTable()`). 앱에 또 적지 않는다(아이폰과
  같은 까닭 — 두 벌이 되면 어긋난다).
- **색·크기는 `ChatSkin`(ChatList.swift)의 값을 그대로 옮긴다.** 카톡을
  픽셀로 재서 얻은 값이라 눈대중으로 바꾸지 말 것.
- 안드로이드에서만 다른 것: 이모티콘 그림은 `file:///android_asset/public/stickers/`
  에 있다(아이폰은 `capacitor://localhost/stickers/`). 키보드는 안드로이드가
  창을 줄여 주므로(`adjustResize`) 아이폰의 `keyboardLayoutGuide` 몫이 없다.

## 아이폰에서 배운 것 가운데 여기도 걸리는 것

- **얼굴은 이모티콘과 같은 캐시에 두지 말 것**(`FaceStore` 자국) —
  코틀린은 Coil이 그림을 맡고, 얼굴은 작게 줄여 따로 담는다.
- **글칸에 초점이 있는 동안 화면을 통째로 다시 만들지 말 것** — 한 글자마다
  목록이 다시 그려지면 끊긴다. 목록은 바뀐 줄만 갈아 끼운다.
- **뒤로 갈 데가 없으면 홈으로** — 알림을 눌러 곧바로 들어온 길이 있다.
  그것은 웹이 정한다(`goBack`). 앱은 `back`·`plain`만 보낸다.

## 화면 전환·뒤로 끌기 층 (`nav/`)

사용자 요청 — `화면 전환 / 뒤로끌기 → Native Navigation Layer`. 대화 화면과
따로, **웹 화면끼리의 전환과 끌어서 뒤로**를 앱이 맡는다(CLAUDE.md의
`화면 전환과 뒤로 끌기는 앱이 맡는다` 꼭지).

```
android/app/src/main/java/com/kkakkung/app/nav/
  NavLayer.kt         ← ios/App/App/NativeNavPlugin.swift의 NavLayer
  NativeNavPlugin.kt  ← 같은 파일의 NativeNavPlugin (웹과의 다리)
```

- `MainActivity`가 `super.onCreate` **뒤에** `NavLayer.install`로 웹뷰를 이
  층 안으로 옮겨 담는다. 대화 화면(`ChatScreen`)도 여기에 얹힌다
  (`NativeChatPlugin.open`의 `host()`) — 그래야 그 위에서도 끌린다.
- 값·신호는 아이폰과 같다(`src/lib/native-nav.ts`). **한쪽만 고치지 말 것.**
- **여기서는 컴파일도 실기기 확인도 못 한다** — `android.yml`이 컴파일을,
  안드로이드 폰이 움직임을 확인한다. 어긋나면 `내 정보`의
  `앱이 화면을 밀고 끌기`를 끄면 웹 길로 돌아간다.
