# 처음 세우기

앱 코드는 다 있다. 남은 건 **Supabase 프로젝트 하나**와 **카카오 로그인 등록**뿐이다.
순서대로 하면 30분쯤 걸린다. 돈은 들지 않는다 (둘 다 무료 등급으로 충분하다).

```
1. Supabase 프로젝트 만들기      →  주소와 anon 키를 얻는다
2. schema.sql 실행               →  테이블·권한·함수가 생긴다
3. 카카오 로그인 등록            →  카카오 → Supabase 연결
4. .env 채우고 로컬에서 확인
5. 나를 총무로 올리기            →  이게 없으면 아무도 승인 못 한다
6. GitHub Pages로 올리기
```

## 1. Supabase 프로젝트 만들기

1. <https://supabase.com> 에서 GitHub 계정으로 로그인
2. **New project** — 이름은 `teetime`, 리전은 **Northeast Asia (Seoul)**

   - **Project URL** — `https://xxxxxxxx.supabase.co`
   - **anon public** 키 — `eyJ...` 로 시작하는 긴 문자열

> **`service_role` 키는 절대 앱에 넣지 않는다.** 그건 모든 권한 설정을 건너뛴다.

> 진짜 방어선은 아래에서 켜는 RLS다.

## 2. schema.sql 실행

좌측 **SQL Editor → New query** 에 저장소의 `supabase/schema.sql` 내용을
**통째로** 붙여 넣고 **Run**.

여러 번 실행해도 안전하게 써 두었다. 나중에 스키마를 고칠 때도 이 파일만
고쳐서 다시 돌리면 된다.

무엇이 생기는지:

| 테이블 | 쓰임 |
|---|---|
| `profiles` | 회원. 카카오로 로그인하면 자동으로 생기고 처음엔 `pending` |
| `rounds` · `signups` | 라운드 모집과 참가 신청 |
| `polls` · `poll_options` · `poll_votes` | 투표 |
| `posts` · `post_comments` | 공지 |
| `rooms` · `messages` | 대화 |

함수도 몇 개 생긴다. 그중 **`join_round`가 이 앱에서 제일 중요하다** —
40명이 동시에 신청 버튼을 눌러도 정원이 깨지지 않게 행을 잠그고 처리한다.
신청은 반드시 이 함수를 거치므로, `signups`에 직접 넣는 권한은 열어 두지 않았다.

## 3. 카카오 로그인 등록

### 3-1. 카카오 쪽

1. <https://developers.kakao.com> → **내 애플리케이션 → 애플리케이션 추가하기**
   - 앱 이름 `teetime`, 회사명은 모임 이름 아무거나
2. **앱 → 플랫폼 키** 에서 **REST API 키**를 복사해 둔다
3. **제품 설정 → 카카오 로그인** → 활성화 **ON**
4. **앱 → 플랫폼 키 → REST API 키**(누르면 상세가 열린다)에서
   - **리다이렉트 URI** — 아래 주소 (1번에서 복사한 Project URL 사용)

     ```
     https://xxxxxxxx.supabase.co/auth/v1/callback
     ```

   - **웹 도메인** — 앱이 돌아갈 주소. `https://<아이디>.github.io`
     (`앱 → 제품 링크 관리 → 웹 도메인` 에도 같은 칸이 있다)

   > **2025년 12월 콘솔 개편으로 자리가 옮겨졌다.** 예전에는 `카카오 로그인`
   > 화면 안에 Redirect URI가 있었지만, 지금은 **앱 키 하위**로 내려갔다.
   > `카카오 로그인 → 일반`을 아무리 뒤져도 없는 게 이 때문이다.
   >
   > `카카오 로그인 → 고급`의 **로그아웃 리다이렉트 URI**는 다른 항목이다.
   > 이름이 비슷해 헷갈리기 쉬운데, 거기 넣으면 로그인은 안 된다.

5. **제품 설정 → 카카오 로그인 → 보안** → **Client Secret** 생성 →
   **활성화 상태: 사용함** 으로 바꾸고 값을 복사해 둔다
6. **비즈 앱으로 전환한다** (`앱 → 일반 → 비즈니스 정보`)
   - 앱 아이콘을 먼저 등록해야 버튼이 열린다
   - 사업자번호는 **없어도 된다** — 본인인증과 카카오비즈니스 약관 동의로 된다

   > **이걸 건너뛸 수 없다.** Supabase는 카카오에 보낼 때 `account_email`을
   > 항상 끼워 넣는데(클라이언트에서 뺄 방법이 없다), 카카오는 이메일 동의항목을
   > 비즈 앱에만 열어 준다. 그래서 개인 앱으로 두면 로그인 화면이 뜨기도 전에
   > `KOE205 잘못된 요청`으로 막힌다. supabase/supabase#36878로 열려 있는
   > 문제라, 그쪽이 고쳐지면 이 단계는 없어진다.

7. **제품 설정 → 카카오 로그인 → 동의항목**
   - `닉네임` — 필수 동의
   - `프로필 사진` — 선택 동의 (없어도 앱은 이름 두 글자로 그린다)
   - `카카오계정(이메일)` — **선택 동의로 켜 둔다.** 앱은 이메일을 쓰지 않지만,
     항목이 꺼져 있으면 위의 KOE205가 난다. 사용자가 동의하지 않아도
     로그인은 된다 (3-2의 `Allow users without an email` 덕분이다).

## 5. 첫 운영자 만들기

**딱 한 번, 손으로 해야 하는 단계다.** 카카오로 로그인하면 `role='pending'`이
되고 `is_member()`가 false라 아무것도 못 읽는다. 승인은 운영진만 할 수 있는데
맨 처음에는 운영진이 하나도 없다 — 닭과 달걀이라 한 번은 DB에서 열어 줘야 한다.

### 방법 A — SQL 한 줄 (간단하다)

카카오로 **로그인부터** 하고(그래야 행이 생긴다) SQL Editor에서:

```sql
-- 지금 누가 들어와 있는지 본다.
-- 전화번호는 다른 표에 있다 (운영진만 보게 나눠 두었다).
select p.id, p.name, p.role, v.phone, p.created_at
  from profiles p left join profile_private v on v.id = p.id
 order by p.created_at;

-- 그중 나를 운영자로. 이름은 방금 로그인한 카카오 닉네임이다.
update profiles set role = 'admin' where name = '홍길동';
```

### 방법 B — 이름·번호로 스스로 열기

새로 차릴 때마다 SQL을 찾아 오기 번거로우면, **가입 신청 화면에서 정해 둔
이름과 번호를 적으면 그 자리에서 운영자가 되게** 해 둘 수 있다. 아래를
한 번 돌리고 대괄호 두 곳을 채운다. **저장소에는 값을 넣지 않는다** —
공개 저장소라 번호가 그대로 남는다.

**전화번호가 `profile_private`으로 옮겨 갔으므로 트리거도 그 표에 건다.**
이름은 `profiles`에 있어 안에서 찾아 본다.

```sql
create or replace function claim_owner()
returns trigger language plpgsql security definer
set search_path = public as $$
declare v_name text; v_role text;
begin
    select btrim(coalesce(name, '')), role into v_name, v_role
      from profiles where id = new.id;

    if v_role = 'pending'
       and v_name = '[이름]'
       and regexp_replace(coalesce(new.phone, ''), '[^0-9]', '', 'g') = '[숫자만 적은 번호]'
    then
        update profiles set role = 'admin' where id = new.id;
    end if;
    return null;
end $$;

drop trigger if exists claim_owner_ins on profiles;
drop trigger if exists claim_owner_upd on profiles;
drop trigger if exists claim_owner_ins on profile_private;
drop trigger if exists claim_owner_upd on profile_private;
create trigger claim_owner_ins after insert on profile_private
    for each row execute function claim_owner();
create trigger claim_owner_upd after update on profile_private
    for each row execute function claim_owner();
```

**`before` 트리거로는 안 된다.** RLS의 `with check`(`profiles_self_upd`)가
before 트리거가 고친 **뒤의** 행을 보기 때문에, 거기서 `role`을 올리면
`role = my_role()`에 걸려 저장 자체가 막힌다. 그래서 `after`에서
`security definer`로 한 번 더 고친다 — 표 주인 권한이라 RLS를 안 탄다.
안쪽 update가 트리거를 다시 부르지만 그때는 `role`이 `admin`이라 조건에
안 걸려 거기서 멈춘다.

> **들어가고 나면 이 문은 닫는 게 좋다.** 번호를 아는 사람은 언제든
> 운영자가 될 수 있기 때문이다.
>
> ```sql
> drop trigger if exists claim_owner_ins on profiles;
> drop trigger if exists claim_owner_upd on profiles;
> drop function if exists claim_owner();
> ```

어느 쪽이든 앱으로 돌아가면 **새로고침 없이** 바로 들어가진다
(내 `profiles` 행이 바뀌는 걸 앱이 실시간으로 듣고 있다).

이제부터 새로 로그인하는 사람은 `내 정보 → 회원 명단`에서 승인하면 된다.

**등급은 넷이다** — 대기 · 회원 · 부운영자 · 운영자.
운영자가 명단에서 `부운영자로`를 눌러 두엇을 임명해 두면 가입 승인과 공지를
나눠 맡을 수 있다. **부운영자 임명은 운영자만** 할 수 있고, 부운영자는
운영진 행을 건드리지 못한다(DB에서도 막아 두었다).

## 7. 알림 켜기 (선택)

앱을 안 보고 있을 때 폰으로 밀어 주는 알림이다. 없어도 앱은 다 돌아간다 —
탭바의 빨간 숫자로도 안 본 것은 알 수 있다.

보내 줄 곳이 있어야 하므로 **Edge Function 하나**를 올린다.

1. **Edge Functions → Deploy a new function** → 이름 `notify`
   - `supabase/functions/notify/index.ts` 내용을 그대로 붙여 넣는다
   - **Verify JWT는 끈다.** 웹훅이 사용자 토큰 없이 부르기 때문이다.
     대신 아래 `NOTIFY_SECRET`으로 문을 잠근다.
2. **Edge Functions → Secrets** 에 네 개를 넣는다
   - `VAPID_PUBLIC_KEY` — **`src/lib/push.ts`에 적힌 공개키와 같아야 한다**
   - `VAPID_PRIVATE_KEY` · `VAPID_SUBJECT`(`mailto:...`) · `NOTIFY_SECRET`(아무 긴 글자)
3. 새 행이 생기면 그 함수를 부르도록 잇는다. **SQL로 거는 편이 낫다** —
   화면의 `Database Webhooks`는 자리가 자주 바뀌어 찾기 어렵고, 표마다
   하나씩 다섯 번을 손으로 만들어야 한다. 아래를 SQL Editor에서 한 번
   돌리면 같은 일이 끝난다 (웹훅도 속은 이런 트리거다).

   ```sql
   create extension if not exists pg_net;

   create or replace function notify_push()
   returns trigger language plpgsql security definer
   set search_path = public, net, extensions as $$
   begin
       perform net.http_post(
           url     := 'https://<프로젝트>.supabase.co/functions/v1/notify',
           headers := jsonb_build_object(
               'content-type',    'application/json',
               'x-notify-secret', '<NOTIFY_SECRET>'),
           body    := jsonb_build_object(
               'type', tg_op, 'table', tg_table_name,
               'record', to_jsonb(new), 'old_record', null)
       );
       return new;
   end $$;

   -- 표마다 하나씩
   -- (messages · rounds · polls · posts · profiles · settlement_shares)
   drop trigger if exists notify_messages on messages;
   create trigger notify_messages after insert on messages
       for each row execute function notify_push();
   ```

   `<프로젝트>`와 `<NOTIFY_SECRET>`을 채우고, 나머지 다섯 표도 같은 모양으로
   만든다. **이 SQL에는 비밀값이 들어가므로 저장소에 커밋하지 말 것.**

   **표를 나중에 더 이어 붙일 때는 `notify_push()`를 다시 만들 필요가 없다.**
   주소와 비밀값이 그 함수 안에 있으므로 트리거만 새 표에 걸면 된다 —
   정산(`settlement_shares`)이 그렇게 뒤에 붙었다.

   ```sql
   drop trigger if exists notify_settlement_shares on settlement_shares;
   create trigger notify_settlement_shares after insert on settlement_shares
       for each row execute function notify_push();
   ```

   **마감했던 투표·모집을 다시 열 때도 알린다.** 이때는 새 행이 아니라
   고쳐진 행이라 `after update`다. 그런데 그대로 걸면 제목을 고치거나
   마감할 때도 알림이 나가므로, **`when` 절로 '다시 열린 순간'만 고른다** —
   발송기는 `UPDATE`가 오면 그게 곧 '다시 열림'이라고 보고 말을 갈라 적는다.
   (`poll_shut()`은 `schema.sql`에 있다. 마감 시각이 지나 끝난 투표는
   `closed`가 아직 false라, 그 칸만 봐서는 다시 열린 것을 못 알아챈다.)

   ```sql
   drop trigger if exists notify_polls_reopen on polls;
   create trigger notify_polls_reopen after update on polls
       for each row
       when (poll_shut(old.closed, old.closes_at)
             and not poll_shut(new.closed, new.closes_at))
       execute function notify_push();

   drop trigger if exists notify_rounds_reopen on rounds;
   create trigger notify_rounds_reopen after update on rounds
       for each row
       when (old.status <> 'open' and new.status = 'open')
       execute function notify_push();
   ```

   **대기가 확정으로 올라갈 때도 알린다.** 자리는 남이 취소할 때 나므로
   본인은 아무것도 안 한 채 확정된다 — 이 알림이 없으면 앱을 직접 열어
   봐야 알고, 라운드 전날 자리가 나도 모르고 안 나오게 된다.

   ```sql
   drop trigger if exists notify_signups_promote on signups;
   create trigger notify_signups_promote after update on signups
       for each row
       when (old.state = 'waitlist' and new.state = 'confirmed')
       execute function notify_push();
   ```

   **조 편성과 입금 독촉.** 둘 다 새 행이 생길 때라 `after insert`다.
   조 편성은 저장할 때마다 `round_groups`가 갈리므로 `update`도 함께 건다
   (바뀐 게 없으면 `set_round_groups`가 아예 안 써서 안 울린다).

   ```sql
   drop trigger if exists notify_round_groups on round_groups;
   create trigger notify_round_groups after insert or update on round_groups
       for each row execute function notify_push();

   drop trigger if exists notify_settle_reminders on settle_reminders;
   create trigger notify_settle_reminders after insert on settle_reminders
       for each row execute function notify_push();
   ```

   **라운드가 코앞일 때 알린다** — 필드·스크린은 **전날 저녁**, 스크린은
   **시작 두 시간 전**에 한 번 더. 이것만은 누가 누른 것이 아니라 **시각이
   되어서** 나가는 알림이라, `schema.sql`의 크론(9번)이 10분마다
   `queue_round_reminders()`를 부르고 그 함수가 `round_reminders`에 줄을
   넣는다. **알림은 그 줄이 들어갈 때 나간다** — 그래서 여기 트리거 하나만
   더 걸면 된다.

   ```sql
   drop trigger if exists notify_round_reminders on round_reminders;
   create trigger notify_round_reminders after insert on round_reminders
       for each row execute function notify_push();
   ```

   지금 무엇이 걸려 있는지는 이걸로 본다.

   ```sql
   select tgname from pg_trigger
   where tgname like 'notify%' and not tgisinternal order by tgname;
   ```
4. 앱에서 **내 정보 → 알림 켜기**

> **함수의 `Verify JWT`를 반드시 꺼야 한다.** 켜져 있으면 Supabase 관문이
> 우리 코드가 돌기도 전에 401로 막는다 — 트리거는 조용히 실패하고 알림만
> 안 온다. 만들 때 그 옵션이 안 보였다면 `Edge Functions → notify →
> Settings`에서 끈다. 인증 없이 열어 두어도 되는 이유는 `x-notify-secret`이
> 문지기이기 때문이다.

**알림이 안 오면 이걸 돌려 본다.** 어디서 막혔는지 한 번에 나온다.

```sql
select 'subs' as kind, count(*)::text as info, '' as body from push_subscriptions
union all
select 'http', coalesce(status_code::text, '(응답없음)'), left(coalesce(content, ''), 300)
from (select * from net._http_response order by created desc limit 5) r;
```

| 나온 값 | 뜻 |
|---|---|
| `subs` 0 | 알림 켜기가 저장되지 않았다 |
| `http` 401 | 함수의 Verify JWT가 켜져 있거나 `x-notify-secret`이 다르다 |
| `http` 500 | 함수 안에서 오류 (내용에 이유가 있다) |
| `http` 200 | 잘 돌았다. 안 오면 기기 쪽 알림 권한을 본다 |
| `http` 줄 없음 | 트리거가 함수를 부르지 못했다 (`pg_net` 확인) |

> **iOS는 홈 화면에 추가한 앱에서만 알림이 온다.** 사파리 탭에서는 켜는
> 버튼이 아예 안 뜬다(그 자리에 안내가 나온다). 안드로이드·PC는 그냥 된다.

> 알림은 **기기마다** 켠다. 폰에서 켜도 PC는 따로 켜야 한다 — 받을 곳이
> 사람이 아니라 기기이기 때문이다. 못 쓰게 된 구독은 발송할 때 만료로
> 확인되면 발송기가 스스로 지운다.

누구에게 가는지는 `supabase/functions/notify/index.ts`의 `planFor()` 하나로
정해진다. 대화는 쓴 사람 빼고 모두, 가입 신청은 총무에게만 간다.

## 나중에: 스토어에 내기

지금은 웹이지만 **코드를 다시 쓰지 않고** 앱으로 감쌀 수 있게 만들어 두었다.

```bash
npm i -D @capacitor/cli
npm i @capacitor/core @capacitor/ios @capacitor/android
npx cap init teetime com.teetime.app --web-dir=dist
npm run build && npx cap add ios && npx cap add android
```

그때를 위해 미리 지켜 둔 것 둘:

- **해시 라우팅**(`/#/rounds`) — 앱 안에서는 파일을 직접 띄우므로 경로
  라우팅이 깨진다. 해시는 그대로 동작한다. `BrowserRouter`로 바꾸지 말 것.
- **`base: './'`**(vite.config.ts) — 상대 경로로 빌드해야 Pages의 하위 경로에서도,
  앱 안에서도 파일을 찾는다.

카카오 로그인만 그때 손이 좀 간다 — 앱에서는 딥링크(`teetime://`)로 돌아와야 해서
카카오 Redirect URI와 `Authentication → URL Configuration`에 한 줄씩 더 넣어야 한다.

## 걸리기 쉬운 곳

| 증상 | 까닭 |
|---|---|
| 로그인 뒤 흰 화면 / 되돌아오지 않음 | Redirect URL을 Supabase에 안 넣었다 (3-2) |
| 카카오에서 `KOE006` | 카카오 쪽 리다이렉트 URI가 Supabase 콜백 주소와 다르다 (3-1의 4번) |
| 콘솔에서 Redirect URI 칸을 못 찾겠다 | 개편으로 **앱 → 플랫폼 키 → REST API 키** 아래로 옮겨졌다 (3-1의 4번) |
| 카카오 동의는 끝났는데 `Error getting user email` / 로그인 실패 | Supabase Kakao 설정의 `Allow users without an email`이 꺼져 있다 (3-2) |
| 카카오에서 `KOE205` (로그인 화면도 안 뜸) | 이메일 동의항목이 꺼져 있다. 비즈 앱 전환 + 이메일 선택 동의 (3-1의 6·7번) |
| 카카오에서 `KOE010` | Client Secret을 만들어 놓고 **활성화 상태를 `사용함`으로 안 바꿨다** (3-1의 5번) |
| 로그인은 되는데 계속 `승인 대기중` | 5번을 안 했다 |
| 목록이 전부 비어 있음 | RLS가 막고 있다 = 아직 `pending`이다. 5번 확인 |
| `설정이 필요합니다` 화면 | `.env`가 없거나 dev 서버를 다시 시작하지 않았다 |
| 실시간이 안 먹음 | `schema.sql` 맨 아래 `alter publication` 부분이 안 돌았다 |
| 알림 켜기 버튼이 없다 | 사파리 탭으로 열었다. iOS는 홈 화면에 추가한 앱에서만 된다 (7번) |
| 알림을 켰는데 안 온다 | 웹훅의 `x-notify-secret`이 Secrets의 값과 다르거나, 함수의 Verify JWT가 켜져 있다 (7번). Edge Functions → Logs에 401이 찍힌다 |
| 배포가 `environment protection rules`로 거부됨 | Pages는 **기본 브랜치에서만** 배포한다. `Settings → General`의 Default branch가 `main`인지, 그리고 `Settings → Environments → github-pages`의 **Deployment branches**에 `main`이 들어 있는지 본다 — 기본 브랜치를 나중에 바꿔도 이 규칙은 옛 이름 그대로 남는다 |
