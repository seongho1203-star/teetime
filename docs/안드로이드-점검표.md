# 안드로이드 전체 점검표

> 사용자 요청 — `아이폰이 완성됐을때 내가 나중에 말하면 안드로이드에게 기능
> 및 디자인부분같은게 정상적으로 작동하는지 전체 체크할수있도록 준비해줘.
> 지금 이후 수정되는것도 추가해서말해줘`.

**아이폰이 기준이다.** 안드로이드(코틀린 · GPT가 만든다)가 아이폰과 **같은
기능 · 같은 모양**으로 도는지를 한 번에 훑는 문서다.

- `docs/안드로이드-따라잡기.md` — GPT에게 넘기는 **일감**(무엇을 어떻게 만들지 · 값).
- **이 문서** — 다 만들었다고 할 때 **맞게 됐는지 확인하는 표**와,
  그 뒤로 아이폰이 바뀐 것을 빠짐없이 쌓아 두는 **변경 기록**.

---

## 0. 사용자가 `안드로이드 점검해줘`라고 하면 — Claude가 하는 순서

Claude는 `android/`를 **고치지 않는다**(CLAUDE.md 사용자 지침). 읽는 것은 된다.

1. **맨 아래 `아이폰 변경 기록`을 먼저 본다.** 지난 점검(`점검 기록`의 마지막
   줄) 뒤에 쌓인 것이 이번에 새로 볼 것이다.
2. **코드를 대 본다** — `android/app/src/main/java/com/kkakkung/app/` 아래를
   읽어 아래 표의 줄마다 `있음 / 없음 / 다름`을 가린다. 값(크기·색·시간)은
   Swift 파일에 적힌 숫자와 견준다. **짐작으로 `있음`을 찍지 말 것** —
   그 자리의 코드 줄을 찾아서 적는다.
3. **다리 이름을 대 본다** — 플러그인 이름·메서드·이벤트·실어 보내는 값이
   아이폰과 한 글자도 안 다른지(`src/lib/native-*.ts`가 기준).
   웹 쪽에서 안드로이드 갈래를 열어야 하는 것(`hasNativeApp()` 등)은
   Claude가 한다 — 따라잡기 문서 5절.
4. **`android.yml`이 초록인지** 본다. 빨가면 원인이 웹 쪽인지부터 가린다.
5. **결과를 세 덩어리로 내놓는다:**
   - 사용자에게: 폰에서 눌러 볼 순서(번호) — 아래 표의 `폰에서 해 볼 것`을
     그대로 옮기되 **없음으로 나온 것은 빼고** 준다.
   - GPT에게 전할 말: `없음`·`다름`을 한 덩어리로(복사 한 번에).
   - 이 문서 맨 아래 `점검 기록`에 날짜 · 아이폰 판 · 안드로이드 판 · 결과 한 줄.
6. 사용자가 폰에서 본 결과(사진·말)를 받으면 표의 줄을 `확인됨`으로 적는다.

**여기서는 둘 다 컴파일도 실행도 못 한다.** 코드 대조가 줄여 주는 것은
`확실히 없는 것`뿐이고, `된다`는 **폰에서만** 확인된다.
