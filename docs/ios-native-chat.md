# iPhone 독립 네이티브 채팅 (43판)

`NativeChatPlugin`이 있는 iPhone에서는 React `Chat`을 마운트하지 않는다.
`NativeChatHost`는 로그인 세션·서버 주소·스티커 목록을 전달하고, 이동·읽음·토큰 갱신 이벤트만 받는다.
브라우저와 기존 바이너리는 기존 채팅을 계속 사용한다.

## 화면 소유권

- `NativeChatViewController`가 머리말, 목록, 입력창, 검색, 참여자, 프로필, 댓글, 반응, 사진·스티커 선택과 사진 보기를 소유한다.
- 기존 요청대로 채팅 안에는 하단 탭바를 두지 않는다. 뒤로 가기와 오른쪽 밀기로 홈에 돌아간다.
- 목록과 입력창은 Auto Layout으로 연결하고 입력창 아래를 `keyboardLayoutGuide`에 묶는다. 웹 높이·스크롤·키보드 보정값을 받지 않는다.
- 홈에 나갈 때 입력 초점을 해제하기 **전에** 위치를 보관한다. 같은 계정으로 돌아오면 같은 컨트롤러와 초안을 복원한다.
- 화면 소유자 ID와 직렬화된 열기/닫기로 이전 화면의 늦은 정리가 새 화면을 닫거나 키보드 모드를 바꾸지 못하게 한다.
- 로그아웃에서는 네이티브 컨트롤러를 폐기한다.

## 통신

`NativeChatService`는 URLSession으로 기존 Supabase REST·Storage·RPC를 호출한다.
회원 JWT와 공개 anon key를 사용하므로 기존 RLS가 그대로 적용된다. DB 변경은 없다.
메시지 전송은 클라이언트 UUID를 보관해 응답 유실 뒤 재시도 시 같은 메시지를 확인한다.
권한 오류나 통신 오류가 나면 입력 내용을 지우지 않는다.

`NativeChatRealtime`은 Supabase Phoenix v1 프로토콜로 메시지·읽음·반응을 구독한다.
20초 heartbeat, 응답 누락 시 재접속, 토큰 갱신을 처리한다. 복귀/재접속 시 기존 메시지의 변경·삭제와 떠나 있던 동안의 새 메시지를 조회한다.
복구 조회의 시작 위치를 고정해 동시에 도착한 실시간 메시지가 중간 대화를 건너뛰게 하지 않는다.

## 회귀 검사

- `.dev/native-chat-check.mjs`: 화면 소유권, 빠른 왕복, 로그아웃, 열기 실패 시 키보드 모드 복구.
- `.dev/NativeChatTests.swift`: 실제 UIKit 컨트롤러에서 20회 홈 왕복 뒤 메시지 ID와 소수점 위치·초안 유지, 전송 후 입력 초점 유지, 목록/입력창 경계, 실패한 전송 보존, 회원 인증 헤더.
- iOS workflow는 시뮬레이터 검사가 통과해야 아카이브와 TestFlight 업로드를 실행한다. 테스트 서버는 URLProtocol로 대체하며 실제 회원 대화를 쓰거나 변경하지 않는다.
- 사진 권한·카메라·천지인/쿼티 전환과 실제 서버 실시간 수신은 TestFlight 실기기에서도 확인한다.

시뮬레이터 결과는 각 Actions 실행의 `NativeChatTests` 첨부에 남는다.
