# 까꿍 Native V2 전환

## 목표

모바일 앱(iOS/Android)에서 React/WKWebView/WebView를 화면, 라우팅, 키보드, 뒤로가기 용도로 사용하지 않는다.
GitHub Pages 웹앱은 별도로 유지한다.

```
Supabase
├─ Web: React (GitHub Pages)
├─ iOS: UIKit + URLSession/WebSocket
└─ Android: Native View/Kotlin + OkHttp/WebSocket
```

## 원칙

1. 기존 Supabase 테이블, RLS, Storage, Realtime을 그대로 사용한다.
2. service_role 키는 앱에 절대 넣지 않는다. 사용자 JWT와 anon/publishable key만 사용한다.
3. iOS/Android 화면 스택은 UINavigationController와 Android native back stack이 단독 소유한다.
4. React Router history와 native navigation을 서로 동기화하지 않는다.
5. 모바일 Native V2 완성 뒤 NativeNav, NativeComposer, WebRoutePageController와 모바일 WebView 화면 전환 코드를 제거한다.
6. 웹앱은 현재 React 화면을 계속 사용한다.

## 현재 확인된 DB 계약

profiles, profile_private, rounds, signups, round_comments, round_groups,
polls, poll_options, poll_votes, poll_comments, posts, post_comments,
settlements, settlement_shares, settle_reminders, notifications, rooms,
messages, message_reactions, room_reads, push_subscriptions.

실제 컬럼과 RLS는 기존 SQL/migrations 및 현재 웹 쿼리를 기준으로 native model을 만든다.

## 배포 전략

native-v2 브랜치에서 iOS/Android를 함께 진행한다.
기능 단위로 native 화면을 완성하고 실기기 확인 후 main에 병합한다.
완전 전환 전까지 현재 웹앱과 운영 DB는 삭제하거나 파괴적으로 변경하지 않는다.
