# 까꿍을 완전한 아이폰 앱으로

사용자 요청 — `까꿍앱을 완전한 네이티브앱으로 바꿔줘. 일단 아이폰만해줘.
이거 완성하고 이후에 안드로이드도 만들거야`.

앞서 검토해 둔 것(`docs/네이티브로-바꾸기.md`)에서 사용자가 `대화 화면만`을
골랐고 그것이 끝났다(`NativeChatViewController`). **이제 나머지 화면도
Swift로 옮긴다** — 그 문서 5번 꼭지의 차례 그대로다.

## 무엇이 바뀌고 무엇이 그대로인가

- **화면이 하나씩 앱 것이 된다.** 옮긴 화면은 웹뷰 **위가 아니라 화면 틀
  (`UINavigationController`)에 밀어 올려진다** — 대화 화면과 같은 자리다.
  그래서 뒤로 끌기·키보드 함께 밀기가 iOS 것이고, 앱이 그리는 화면끼리는
  웹뷰를 거치지 않는다.
- **DB·규칙은 한 줄도 안 바뀐다.** 앱은 지금의 웹과 똑같이 회원의 JWT로
  Supabase REST를 부르고(`NativeChatService.request`) RLS가 막는다.
  **`service_role` 키는 앱에도 절대 안 들어간다.**
- **로그인·알림·카카오는 그대로 껍데기 것이다**(`lib/native-push.ts` ·
  `signInWithKakao`). 그 둘은 이미 네이티브다.
- **웹은 회원들이 쓰지 않는다**(사용자 규칙 — 쉰 명이 쓸 예정이던 것이지 진짜로
  쓰는 것이 아니다). **진짜 제품은 아이폰·안드로이드 앱**이다. 웹 화면은 아직
  안 옮긴 화면의 자리 · 앱 화면이 안 열릴 때 돌아갈 예비 길 · 헤드리스로 규칙을
  재 보는 자리로만 남고, 웹을 위해 무엇을 새로 만들지 않는다. 앱에서도
  **스위치가 꺼져 있으면 웹 화면**이다(아래).

## 단계

한 판을 다 짓고 켜는 것이 아니라 **켜는 스위치를 두고 화면 하나씩 밀어
올린다.** 스위치가 꺼져 있으면 아이폰 앱도 지금처럼 웹 화면을 쓴다.

| 단계 | 넣는 것 | 확인 |
|---|---|---|
| **1** | 문(`NativeApp` 플러그인 · `NativeScreenController` 뼈대 · 웹 다리 `lib/native-app.ts`) · **회원 명단**(찾기·차례·운영진 줄·승인·임명·추방) | 빌드 초록 · 폰에서 명단이 뜨고 승인이 되는가 · `←`와 가장자리 끌기로 나오는가 |
| 2 | 읽는 화면 — 공지 목록·상세 · 투표 목록·상세(표 던지기 포함) · 라운드 목록·상세(신청·취소 포함) · 알림함 · 사용자 가이드 | 폰 |
| 3 | 쓰는 화면 — 모집 열기·고치기 · 투표 만들기 · 공지 쓰기 · 정산(만들기·입금·독촉) · 조 편성 · 내 정보(프로필·알림 설정) | 폰 |
| 4 | **홈과 탭바** — **먼저 했다**(위 꼭지). 여기까지 오면 웹뷰가 로그인 화면 몫만 남는다 | 폰 |
| 5 | 알림 누르면 그 화면으로(딥링크) · 뱃지 · 실시간(`useRealtime` 몫) | 폰 |
| 끝 | 스위치를 없애고 아이폰 기본을 앱 화면으로. 웹 화면 코드는 예비 길·헤드리스 검사 몫으로만 남긴다 | — |
| 그다음 | 안드로이드 — 같은 차례를 코틀린으로(`docs/안드로이드-네이티브.md`) | — |

**차례가 이런 까닭** — 회원 명단이 첫 화면인 것은 **읽기 + 쓰기가 한 화면에
다 있으면서 짜임이 단순해서**다(표 하나 · 목록 하나). 여기서 문·뼈대·통신·
권한 갈래(`is_admin`·`is_owner`·`is_super`)를 한 번에 다 밟아 두면 다음
화면들은 같은 틀에 내용만 바꿔 넣는 일이 된다.

## 켜는 방법 (시험 중)

1. TestFlight에서 새 판을 받는다(`내 정보` 맨 아래 `버전 1.NNN`으로 가린다).
2. `내 정보` 맨 아래 **`🧪 시험 중: 앱 화면 (회원 명단)`** 스위치를 켠다.
3. `내 정보 → 회원 명단`을 누른다 — Swift 화면이 뜬다. 끄면 예전 웹 화면이다.

## 여기서 확인할 수 있는 것과 없는 것

- **Swift는 여기서 컴파일할 수 없다.** GitHub의 맥(`ios.yml`)이 알려 준다 —
  밀면 10~15분 뒤에 초록/빨강이 갈린다. 실제 움직임은 TestFlight로 받아
  봐야 안다. **그래서 화면마다 웹 예비 길(스위치)을 먼저 둔다.**
- **웹 쪽은 헤드리스로 본다**(`.dev/behave.mjs`) — 플러그인이 없는 판에서
  예전 화면이 그대로인가.
- 앱 화면이 하나씩 늘 때마다 `NativeAppPlugin.screens`(Swift)와
  `NATIVE_SCREENS`(`lib/native-app.ts`)에 그 주소를 더한다.
  **한쪽만 고치지 말 것** — 웹이 앱 화면으로 보냈는데 앱이 모르면
  `앱이 아직 모르는 화면입니다`로 거절하고 웹은 오류 안내를 띄운다.

## 짜임

```
ios/App/App/
  NativeAppPlugin.swift        ← 문(`NativeApp`) · AppSkin(색) · NativeScreenController(머리말·← ·뒤로 알림)
  NativeAppData.swift          ← NativeChatService에 얹은 조회 (profiles · profile_private · attendance_counts · role 고치기)
  MembersViewController.swift  ← 1단계: 회원 명단
  PostViewController.swift     ← 2단계: 공지 상세 + 댓글
  AlertsViewController.swift   ← 2단계: 알림함(🔔)
  RoundViewController.swift    ← 2단계: 라운드 상세(신청·취소 · 조별 명단 · 정산 보기 · 댓글 · 운영)
  PollViewController.swift     ← 2단계: 투표 상세(표 던지기 · 현황 탭 셋 · 댓글 · 마감/지우기)
  HelpViewController.swift     ← 2단계: 사용자 가이드(글은 웹 `lib/guide.ts`에서 받는다)
  ShellController.swift        ← 앱 껍데기(탭바 · 탭 뼈대 · 카드·표 조각)
  ShellTabs.swift              ← 공지 · 라운드 · 투표 목록 탭
  HomeTab.swift                ← 홈 탭
src/lib/native-app.ts          ← 플러그인 다리 · 스위치 · NATIVE_SCREENS
src/screens/NativeScreen.tsx   ← 주소마다 앱 화면인지 웹 화면인지 가르는 자리 (MembersRoute · PostRoute · AlertsRoute · RoundRoute · PollRoute · HelpRoute)
```

- **웹과 오가는 말은 대화 플러그인과 같은 꼴이다** — `open({screen, path,
  user, token, url, key, slide})` · `close` · `session`, 그리고 `event`
  (`back` `plain` · `navigate` · `auth`). 토큰이 만료되면 앱이 `auth`를 보내고
  웹이 `refreshSession` → `session`으로 새 토큰을 준다(대화와 같다).
- **`lib/tabs.ts`의 `/chat` 특례가 `nativeRoute()`로 넓어졌다** — 앱이 그리는
  주소는 대화든 회원 명단이든 같은 길이다(웹뷰에 앞 화면 그림을 깔고 ·
  `NativeNav`에는 판만 쌓고 · 웹은 안 민다).
- **통신은 `NativeChatService` 하나다.** 이름에 `Chat`이 붙어 있지만 하는
  일은 Supabase REST 한 번 부르기라 그대로 쓴다 — 두 벌로 만들면 401 갱신
  고리(`authNeeded`)가 둘이 된다. 화면마다 필요한 조회는 `NativeAppData.swift`에
  extension으로 얹는다.
- **색은 `AppSkin`(tokens.css의 값 그대로)이다.** 글꼴은 폰 기본
  (Pretendard가 앱에 없다) — 대화 화면과 같은 사정이다.
- **규칙은 웹과 같아야 한다.** 이름표(`83/신성호/광산구`) · 차례 넷(이름·
  나이·지역·성별, 모르는 값은 뒤로) · 찾기 문턱(`FIND_AT` 12) · 참석 횟수는
  운영진만(`attendance_counts`가 막으면 줄째 안 적는다) · 임명은 한 계단씩.
  **한쪽만 고치지 말 것.**

## 순서를 바꿨다 — 홈·탭바(앱 껍데기)를 먼저

사용자 요청 — `그냥 지금 바로 홈·탭바까지 앱으로 만들어줘`. 화면을 하나씩
옮기며 스위치로 오가는 동안 **웹 화면과 앱 화면이 맞닿는 자리마다 자국이
났다**(앱 알림함 → 웹 라운드 → 다시 앱 알림함에서 두 겹·터치 안 됨). 경계를
하나씩 쫓는 대신 **경계 자체를 없애는 쪽**으로 갔다.

- **`ShellController`(UITabBarController)** — 로그인이 끝나면 웹이
  `NativeApp.shell()`을 불러 세운다. 틀은 `[뿌리(웹뷰), 껍데기]`가 되고 그
  뒤로 사람이 보는 것은 전부 앱 화면이다. 로그아웃하면 `shellOff()`.
- 탭 넷은 앱이 그린다 — **홈**(`HomeTab.swift`) · **공지·라운드·투표 목록**
  (`ShellTabs.swift`). `대화` 탭은 웹에 `/chat`을 열라고 해 대화 플러그인이
  그 위에 세운다(지금까지의 길).
- 앱이 그리는 상세(공지·알림함·회원 명단)는 웹을 거치지 않고 틀에 바로
  밀어 올린다(`shell.push` — 그 화면의 `navigate`는 다시 `shell.go`로 온다).
- **아직 웹인 화면**(라운드·투표 상세 · 모집 열기·투표 만들기·공지 쓰기 ·
  정산 · 내 정보 · 가이드)은 웹에 그 주소를 열라고 한다 → `pushState` →
  `NativeNav.push` → 웹뷰를 든 page가 껍데기 위에 선다(iOS 26 시스템 웹
  전환). 돌아오면 `NavLayer`가 웹뷰를 뿌리로 되돌린다. **iOS 26 아래에서는
  이 길이 없다** — 그 기기는 스위치를 켜지 말 것(웹 화면 그대로다).
- 웹 쪽은 `NativeShellSync`(`NativeScreen.tsx`) 하나다 — 세우고·내리고·앱이
  열어 달라는 주소를 열고·알림 딥링크처럼 웹이 먼저 움직인 것을 앱에 알린다.
  껍데기가 켜져 있으면 웹 탭바는 안 그린다(`TabBar.tsx`).
- **껍데기 뒤의 웹뷰는 rAF가 안 돈다.** 웹으로 여는 길(`대화` · 아직 웹인
  화면)에서 `requestAnimationFrame`만으로 기다리면 영영 멈춘다 — 214판에서
  `대화` 탭이 그래서 안 눌렸다. `afterPaint()`(150ms 그물)를 쓴다.
- **탭의 숫자** — 빨강은 내가 안 본 것(공지·대화·승인), 잔디는 열려 있는
  개수(라운드·투표). 대화는 서버의 `room_reads`로 센다(웹은 기기의
  `teetime:seen:`을 보므로 몇 마디 어긋날 수 있다). 실시간은 아직 없다 —
  탭이 보일 때마다·당겨서 다시 받는다.
- **날씨는 좌표가 있는 라운드만** — 이름으로 찾는 예비 길(`courses.ts`)은
  앱에 없다.

## 2단계 — 지금까지 옮긴 것

- **공지 상세(`/board/<id>`)** — 제목·글쓴이·본문 · `📣 대화방에 공유`(누구나 ·
  없는 칸을 하나씩 빼며 다시 넣는 `shareToChat`) · 운영진의 `맨 위에 고정`·
  `지우기` · 댓글(달기·지우기). **댓글 칸은 화면 아래 붙박이 바**다 —
  `keyboardLayoutGuide`에 묶여 키보드와 한 몸으로 오르내린다. `수정`은
  머리말 오른쪽이고 쓰는 화면(`/board/<id>/edit`)은 아직 웹이라 그리로 넘긴다.
- **알림함(`/alerts`)** — 여는 순간 다 읽음으로 찍고, 안 읽었던 줄은 화면이
  얼려 둔 `fresh`로 가른다(빨간 띠 + `N`). 90일 지난 것은 여기서 지운다.
  줄을 누르면 알림의 `url`을 웹에 넘겨 **그 건으로** 간다.
- **주소에 `:id`가 있는 화면은 uuid로만 걸린다** — `/board/new`·`/board/<id>/edit`
  같은 쓰는 화면은 3단계까지 웹이다(웹 `matches()` · Swift `UUID(uuidString:)`).
- **라운드 상세(`/rounds/<id>`)** — 표 줄·장소 · 정보 표(날짜·티오프/시작·정원·
  그린피/게임비 · 필드면 캐디·카트 — 칸 수는 늘 짝수) · `📣 대화방에 공유`
  (지난·취소된 것은 빼고 누구나) · `📋 같은 조건으로 새로 열기`(스크린만) ·
  전달 내용(노란 쪽지) · 참가 확정(조가 짜여 있으면 조별로 · `내 조` 표 ·
  조별 시각 · 빈 자리 줄 · 운영진의 `✕`) · 대기 · **정산은 보는 쪽만**(내 몫
  크게 · `입금완료` · 계좌 복사 · `토스로 보내기` · 누구 몫이 얼마 · 지우기) ·
  운영(모집 마감·다시 열기·취소·되돌리기·지우기 — 연 사람과 운영진) · 댓글.
  **신청 단추는 화면 아래 붙박이 바**(웹의 `sticky`)이고 신청·취소는 DB 함수
  (`join_round`·`leave_round`)가 한다 — 정원을 여기서 안 센다. 댓글 칸은
  키보드에 묶인 바인데 **적는 동안만 뜬다**(아래에 신청 단추가 이미 있어
  바를 둘 세울 자리가 없다) — 댓글 카드의 `댓글 남기기`를 누르면 올라온다.
  `수정`·`조 편성`·`같은 조건으로 새로 열기`·**정산 만들기**는 3단계에서
  앱 화면으로 옮겨 갔다(아래).
- **투표 상세(`/polls/<id>`)** — 위는 던지는 곳(항목 · 이름 없이), 아래는
  읽는 곳(`항목별` · `멤버별` · `미참여 N` — 익명이면 카드째 없다) · 댓글 ·
  만든 사람과 운영진의 `마감`/`다시 열기`(다시 열 때 지난 마감 시각을 지운다)·
  `지우기`. 참여 수는 회원(대기·추방 제외) 가운데 표를 던진 사람이다.
  **끝났는데 결과 카드를 안 남긴 투표는 앱도 `post_poll_result`를 부른다**
  (`announceClosedPolls` — 홈·투표 탭·투표 상세 셋이 부른다. 웹과 같다).
  `수정`(`/polls/<id>/edit`)은 아직 웹이다.
- **사용자 가이드(`/help`)** — **글은 `src/lib/guide.ts` 한 곳에만 있다.** 웹
  `Help.tsx`도 거기서 그리고, 앱은 `NativeScreenHost`가 `open({guide})`로
  통째로 실어 보낸 것을 그린다(대화가 이모티콘 추천 표를 받는 방식). 표시는
  `**굵게**`·`((곁말))` 둘뿐이고 웹 `Rich`와 Swift `GuideText`가 같은 규칙으로
  푼다 — **Swift에 글을 적지 말 것.** `홈 화면에 추가`(`webOnly`)는 앱에서 뺀다.
  껍데기가 직접 `/help`를 열면 글이 없어 웹에 맡긴다(`make`가 `nil`).
- **2단계는 끝났다.** 3단계(쓰는 화면)는 아래.
  **목록 화면(공지·투표·라운드 탭)은 탭바가 웹이라 4단계에서 홈과 함께 간다.**

## 3단계 — 쓰는 화면 (진행 중)

- **뼈대는 `FormScreen.swift` 하나다**(`FormScreenController`). 카드 기둥 +
  **아래 붙박이 저장 바**(웹 `.form-actions`)이고, 바는 `keyboardLayoutGuide`에
  묶여 키보드와 한 몸으로 오르내린다. **글칸이 아닌 데를 누르면 키보드를
  내린다**(웹 `lib/keyboard.ts`와 같은 규칙). 글자 수 한도는 **조합이 끝난
  뒤에**(`markedTextRange == nil`) 자른다 — 조합 중에 자르면 한글이 깨진다.
  칸은 `FormTextField`(한 줄) · `FormTextView`(여러 줄 · 자란다) · `switchRow`.
- **한 번 그린 폼은 다시 받지 않는다**(`built`) — 되살아날 때(`revive` →
  `loadScreen`) 적던 글이 날아가면 안 된다.
- **공지 쓰기·고치기**(`/board/new` · `/board/<id>/edit`, `PostEditViewController`)
  — 새 글은 운영진만, 고치는 것은 쓴 사람과 운영진만(웹 `PostEdit`와 같은 잣대).
  새로 올리면 그 글로 **바꿔치기**해 가고(`replace`), 고친 것은 **뒤로 간다** —
  밑에 깔린 그 글이 돌아올 때 다시 받는다.
- **투표 만들기·고치기**(`/polls/new` · `/polls/<id>/edit`, `PollEditViewController`)
  — 웹 `PollEdit`와 같은 규칙(표가 들어오면 `익명`·`복수 선택` 잠김 · 항목 두 개
  이상 · 마감 시각 필수 · 새로 올릴 때만 지난 시각을 막음). **날짜·시각은
  시스템 `UIDatePicker`(`WhenPicker`)이고 날짜 항목은 `UICalendarView`다** —
  웹이 달력을 직접 그린 까닭(웹뷰 안의 영어 창)이 네이티브에는 없다.
  `ko_KR` · 한국 시간대로 못박는다. 달력은 iOS 16부터라 그 아래에서는 안 보인다.
  새로 올리면 웹처럼 **목록으로** 간다.
- **모집 열기·고치기**(`/rounds/new` · `?from=` · `/rounds/<id>/edit`,
  `RoundEditViewController`) — 웹 `RoundEdit`와 같은 규칙(종류부터 고른다 ·
  캐디·카트는 한 줄에 하나 · 스크린으로 저장하면 캐디·카트·좌표를 null로 ·
  `title`·`opens_at`은 안 보낸다 · 베끼면 시각만 비운다). **골프장 574곳은
  웹이 실어 보낸다**(`open({courses})` · `lib/courses.ts`) — 찾는 규칙은
  `CourseBook`이 웹 `courseGeo`·`searchCourses`와 같게 옮긴 것이다.
  목록 없이 껍데기가 직접 부르면(`make`가 `nil`) 웹에 맡긴다 — 가이드와 같다.
  금액 칸은 `WonTextField`(웹 `WonField`와 같은 커서 셈).
- **정산 만들기**(`SettlementEditViewController`) — **주소가 없는 시트다.**
  라운드 상세의 `＋ 정산`을 누르면 그 위에 뜬다(웹에서도 상세 안에 접힌 폼이라
  히스토리 한 칸을 만들 이유가 없다). `goBack`을 덮어 닫기만 하고, 적은 것이
  날아가지 않게 아래로 끌어 닫지 못한다(`isModalInPresentation`). 규칙은 웹
  `SettlementForm`과 같다(회원 전체에서 고르되 참가자를 앞에 · `그 외` 접기 ·
  열둘 넘으면 찾기 칸 · 1/N 10원 내림 · 예외 금액 · 몫은 정산을 만든 뒤에).
  **고르는 줄은 누를 때마다 새로 만들지 않고 칠만 갈아 끼운다** — 찾기 칸에
  초점이 있을 때 다시 만들면 키보드가 내려가고 한글 조합이 깨진다.
- **공용 목록은 껍데기가 한 번 받는다**(`NativeAppPlugin.shared`) — 웹이
  `shell()`에 골프장·은행·가이드 글을 실어 보내고, `make`가 그것을 바탕에 깐다.
  그래서 껍데기가 직접 여는 화면(모집 열기·가이드·`＋ 정산`)도 네이티브로 뜬다.
  원본은 웹 한 곳(`lib/courses.ts`·`BANKS`·`lib/guide.ts`)이다.
- **조 편성**(`/rounds/<id>/groups`, `RoundGroupsViewController`) — 웹
  `RoundGroups`와 같은 규칙(모집을 연 사람과 운영진만 · 확정자만 · 빈 조 하나를
  늘 더 보여 줌 · 조가 여섯을 넘으면 칩 대신 메뉴 · 눌린 칩을 다시 누르면 미배정 ·
  `set_round_groups`에 **확정자 전원**을 싣는다 · 쓰는 조의 시각만 보낸다).
  **나누는 규칙은 Swift `GroupRules`에 옮겨 적었다** — 누르는 순간 화면 안에서
  나눠야 해 다리로 부를 수가 없었다. 원본은 `src/lib/groups.ts`이고 함수 이름도
  같게 두었다(`.dev/groups-check.mts`가 웹 쪽을 붙든다). **한쪽만 고치지 말 것.**
  조별 시각은 시·분만(`UIDatePicker` `.time`) — 처음 누르면 라운드 시각에서
  시작하고 `✕`로 지운다. 저장하면 뒤로 가서 라운드 상세가 다시 받는다.
- **정산 현황**(`/settle`, `SettleViewController`) — 웹 `Settle`와 같은 규칙
  (최근 30건 · 몫은 딸려 받기 · 기본은 `내가 올린 것` · `전체`는 총무·운영진에게
  남이 올린 것이 있을 때만 · 맨 위는 안 걷힌 금액 하나 · 다 걷힌 정산은 개수만 ·
  **안 낸 사람만** 세우고 누르면 입금완료 · `입금 알림 보내기`는
  `settle_reminders`에 한 줄 — 남의 정산이면 그 사람 계좌라고 한 번 더 알린다).
  `settle_reminders`·라운드 이름을 못 받으면 그 줄만 빠진다. 아래로 끌어 다시 받는다.
- **내 정보**(`/me`, `MeViewController` · 프로필 수정은 그 위의 시트
  `MeEditViewController`) — **이 화면만 반은 웹에 부탁한다.** 알림 켜기·대화
  알림(푸시 플러그인·구독 줄) · 로그아웃·탈퇴(웹이 든 로그인 세션) · 시험
  스위치(웹의 `localStorage`) · 내 값 다시 받기(`useAuth`)는 **웹이 쥐고 있는
  것**이라 두 벌로 만들면 어긋난다. 앱이 `action` 이벤트(`name`·`value`)로
  부탁하면 웹(`MeRoute`)이 하고 **`NativeApp.reply`로 답한다**(알림 켜는 동안의
  걸음도 `step`으로 흘려 보낸다). 탈퇴 순서(알림 → 사진 → 계정)는
  `src/lib/account.ts`의 `leaveAccount` 하나를 웹 화면과 같이 쓴다.
  **앱이 직접 하는 것**은 보이는 것 전부 · 프로필 사진(400px · `avatars/<내 id>/<시각>.jpg`) ·
  프로필 수정(여섯 칸 다 필수 · `profiles`를 먼저, `profile_private`는 고쳐 보고
  없으면 넣는다)이다. 음력 생일의 올해 양력 날짜는 웹이 셈해 실어 보낸다
  (`lib/lunar.ts` — Swift에 옮기지 않는다). **웹이 알림 상태를 물어 두고
  열어야만 뜬다** — 껍데기가 직접 부르면 `make`가 `nil`이라 웹에 맡긴다.
  **`🧪 시험 중: 앱 화면` 스위치는 여기에도 있다** — 앱 화면이 어긋날 때 웹으로
  돌아가는 유일한 문이라 빼지 말 것.
- **3단계는 끝났다.** 다음은 5단계(알림 딥링크·뱃지·실시간).

## 1단계에서 아직 안 한 것

- 얼굴을 눌러 여는 전체화면 프로필(`ChatProfile`) — 2단계에서 붙인다.
- 목록 한가운데서 끌어 뒤로(`BackDrag`) — **왼쪽 가장자리 끌기와 `←`만
  된다.** 대화 화면과 같은 사정이다(키보드까지 함께 미는 길이 그것뿐이다).
- 실시간 갱신 — 화면에 들어올 때와 무엇을 바꾼 뒤에 다시 받는다.
  당겨서 새로고침도 된다.
